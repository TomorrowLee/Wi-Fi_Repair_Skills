# 家庭 Wi-Fi 分步诊断与修复

在发生问题的设备和位置做测试。先确认网络接口、实际 Wi-Fi 网关、应用症状、代理/VPN 状态。宽带套餐速率仅在判断是否达标时需要。用户已经提供的读数直接使用，注明时间或采样范围。收到一段终端输出，先解释它，再给一个下一步。

按平台选用 [macOS 操作手册](references/macos.md) 或 [Windows 操作手册](references/windows.md)。用[虚构演练案例](references/case.md)理解如何处理相互矛盾的测量。工作机或云环境不能代表用户的无线链路；只有能确认在问题机器和目标网络上运行时，才把读数记为实测。

## 按顺序取证

| 顺序 | 单次操作 | 应保留的证据 |
|---|---|---|
| 1a | 查看当前无线连接 | 实际频段、主信道、宽度、RSSI、噪声、协商速率。缺失字段写“未提供”。 |
| 1b | 等上一步结束，再扫描附近无线网络 | 把主信道、宽度和可用的信号强度按频段分组。按重叠范围估计候选，不把 AP 数量当作信道利用率。 |
| 2a | 读取接口计数 → ping 无线网关 30 包 → 再读计数 | 收发数量、丢包、最小/平均/最大 RTT、可用的波动指标、错误和丢弃增量。 |
| 2b | ping 1.1.1.1，30 包 | 与网关比较。目标无回包时记录 ICMP 情况，不推断网站也不可用。 |
| 2c | 到 1.1.1.1 最多追踪 5 跳 | 保存各跳响应地址和时间。重复地址、星号及虚拟接口单独标注。 |
| 3 | 向 1.1.1.1、8.8.8.8 和已核实的路由器 DNS 逐次查询 | 三个相同域名、相同类型；记成功数、失败类型、成功样本中位数和答案。路由器可能没有 DNS 服务。 |
| 4 | 单独做一次网络质量测试 | 平台、工具、模式、目标、上下行 Mbps、空闲/负载延迟。Apple 另记 RPM 与评级。 |

每次只启动一项，上一项结束后再继续。DNS 循环内也串行。测速本身可能同时产生上下行负载，这是工具的测试模式；测速期间不要另开 ping、下载或另一个测速。没有真机权限时，说明哪个字段或测试受限，只给用户下一条本机操作。权限报错、无设备、字段缺失分别记录，不作零丢包、零错误或故障证据。

## 根据证据选择下一步

| 观察 | 下一步及验证 |
|---|---|
| 信号弱或网关延迟、丢包随位置变化 | 同一台设备移近路由器，保持其余条件相同再测网关。若已有网线，也可在另一轮做有线对照。 |
| 信号强、同频记录多，网关样本稳定 | 暂保留信道。若故障能复现且网关同时变差，再单独试一个宽度或信道，用原位置、原症状和网关测量复核。 |
| 网关稳定，但外部响应慢、跳数异常或只有代理应用慢 | 核对到目标的接口和代理分流。可以使用同 Wi-Fi 上原本直连的另一台设备作对照，注明设备差异。遵守用户指定的应用出口及断线保护。 |
| 两个公共 DNS 多次失败，路由器 DNS 能返回有效答案 | 先区分直查和系统/应用实际使用的 DNS。若症状符合首次解析等待，按对应手册只改当前设备的 DNS，保留回退值。 |
| 有带宽，空闲延迟已高 | 分析测试终点、出口和路径距离。吞吐量不足以解释请求往返时间。 |
| 空闲正常，负载延迟明显上升且卡顿同时出现 | 结束测速后单独暂停占带宽的任务，再复现。证实与负载相关后才讨论限速或队列管理。 |

## 修复与交付

1. 改之前记下接口、自动或手动、原值和症状基线。能在单台设备验证的改动先在单台做；共享路由器改动要考虑其他设备的断线影响。
2. 保持地点、应用、代理出口、测试方法和目标尽可能一致。每次改一个变量。对网页首开优先观察首次显示和资源加载的区别，注明浏览器缓存、加密 DNS、CDN 的影响。
3. 分别核验“配置已保存”“实际解析/链路已复测”“用户原症状改善”。缺一项就在结果中标明。无改善时恢复原值，再测下一个假设。
4. 输出四行：**已确认**（数字、单位、样本数）、**优先排查**（证据及其他解释）、**本次改动与回退**、**复测结果或下一项**。
5. 对外展示结果时，用“家庭路由器”“虚拟接口”等代称，移除个人 SSID、BSSID/MAC、真实公网地址、设备名、节点名和完整诊断报告。公共测试目标可保留。

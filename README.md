# Wi-Fi Repair Skills · 家庭 Wi-Fi 分步诊断与修复

一个面向 **macOS、Windows 10 和 Windows 11** 的中文 AI 技能。针对 Wi-Fi 满格却卡、网页首次打开慢、视频会议时断时续或代理开启后测速异常，按“无线连接 → 家庭网关 → 公网路径 → DNS → 负载响应 → 单项修复与复测”的顺序收集证据。每项结束才开始下一项。

适合希望 AI 带着操作的家庭用户，也适合有终端读数、想知道下一步该查什么的人。多数诊断使用系统自带命令；Windows 的网络质量测试可使用浏览器。技能本身是说明文件，不会在安装时修改电脑或路由器。

## 一轮诊断具体做什么

1. **固定观察条件。** 记录设备、问题位置、大致时段、代理状态和具体症状。网页“空白几秒”和“页面出来后图片很慢”要分别描述。
2. **查看无线链路，再扫描周围频谱。** 信道宽度决定哪些网络真正重叠。例如主信道 36 和 48 都用 80 MHz 时，可以占用同一频段。能看到的 AP 数量只反映附近可见网络，仍要结合信号强度、可能的自家多接入点和实际忙碌程度判断。
3. **先测家庭网关 30 包，结束后再测公网 30 包。** Wi-Fi 网卡错误和丢弃取网关测试前后的差值。出现权限错误要写“未测”；只有实际成功采样才能报告丢包率。
4. **单独做最多五跳的路由追踪。** 目标提前到达也是有效结果。中间跳超时、相同地址反复出现、公网回应异常快时，先查路径和代理机制，避免把现象误报为运营商故障。
5. **串行对比三个 DNS。** 两个公共 DNS 加经核实的路由器 DNS，依次查询相同的三个域名，分开记录成功数、失败类型与成功样本的中位数。显式向 DNS 服务器查询和浏览器真实使用的解析路径可能不同。
6. **单独测网络质量。** 上下行吞吐量用于衡量传输能力；空闲与负载延迟用于判断忙时等待如何变化。注明工具、模式和代理状态，同平台用相同工具进行前后对比。
7. **选一个有证据支持的修复。** 保留原值，只改变 DNS、信道宽度、摆放位置等因素中的一个，再重复原来失败或变慢的操作。报告分别写明设置是否保存、路径是否复测、原症状是否改善。

## 从 Mac 换到 Windows，具体有哪些变化？

| 项目 | macOS | Windows 10 / 11 |
|---|---|---|
| 当前无线与周边扫描 | Option 点击 Wi-Fi；无线诊断扫描或 system_profiler | netsh wlan show interfaces 和 netsh wlan show networks mode=bssid；权限与驱动会影响结果 |
| 信号、噪声、宽度 | 常能看到 dBm、MHz，可计算信噪比 | 常见信号百分比；噪声、协商宽度不可见时留空，不从百分比推算 |
| 找物理网关与错误 | 先找 Wi-Fi 设备，再查 ipconfig、netstat | 按无线网卡名称或 ifIndex 查 Get-NetIPConfiguration、Get-NetAdapterStatistics |
| ping 和前五跳 | ping -c 30；traceroute -n -m 5；追踪默认 UDP | ping.exe -n 30；tracert.exe -d -h 5；追踪使用 ICMP Echo |
| DNS 计时 | dig 的 Query time | Resolve-DnsName 加 Stopwatch 测命令耗时；计时边界和超时策略不同 |
| 带宽与延迟 | networkQuality -v，保留 Mbps、ms 和 RPM | 浏览器测速记录 Mbps、空闲及上下行负载 ms；不生成 Apple RPM |
| 恢复 DNS | 在 Wi-Fi 详情恢复自动或原手动列表 | 按网卡和地址族恢复；Windows 10 可使用 ncpa.cpl，Windows 11 也可使用网络设置 |

## 如何读结论

- **网关丢包，移近路由器后消失**：先处理覆盖或无线干扰，再判断外部带宽。
- **网关稳定，但公共 DNS 频繁超时**：用同一批域名对照路由器 DNS，再测试系统或浏览器的首次访问。
- **空闲时已慢，只有代理应用受影响**：记录出口和端点，做受控对照。需要固定出口的应用继续遵循其策略。
- **只有跑满上传时会议才卡**：对照空闲与上传负载下的响应，在另一轮暂停上传验证，之后再考虑流量管理。

本仓库仅含通用命令、公开测试服务与虚构案例。使用者共享结果时只需提供相关指标，可隐去网络标识和设备地址。真实环境一直无法访问时，技能会标明缺失的证据，给出最小的下一步。
